\chapter{QNX-Compatible C Library}
\label{chap:libqsoe}

\section{Purpose}

QSOE provides a C library layer --- \emph{libqsoe} --- that exposes
QNX-compatible IPC and threading primitives.  This library is
linked by all user-space programs (including taskman itself, with a
build-time flag that bypasses self-IPC) and translates QNX API calls
into the appropriate seL4 system calls and capability operations.

\emph{libqsoe} lives at \texttt{userland/libqsoe/} as a standalone
static library.  It is built on top of musl libc, which provides
standard POSIX/C functions, and extends it with the QNX-specific
interfaces.  The two libraries are independent build artefacts: musl
patches are confined to \texttt{userland/libc/}, libqsoe does not
modify musl source.

\section{Core IPC functions}

\subsection{Channels}
\label{sec:channels}

\begin{lstlisting}[language=C]
int ChannelCreate(unsigned flags);
int ChannelDestroy(int chid);
\end{lstlisting}

A \emph{channel} is the server-side IPC endpoint.  Creating a channel
allocates an seL4 Endpoint object and registers it in the process's
channel table.

\paragraph{\texttt{ChannelCreate(flags)}}
Creates a fresh, empty channel owned by the caller.  Returns a
non-negative \texttt{chid} on success, or \texttt{-1} with \texttt{errno}
set on failure.  The \texttt{flags} argument is stored in the channel's
registry entry for future interpretation by \texttt{MsgReceive} and
related calls; v0.x accepts any value.  Internally:

\begin{itemize}
    \item \emph{libqsoe} sends a \texttt{CHANNEL\_CREATE} request to
          \texttt{taskman}.  The request carries the caller's choice of
          \texttt{chid} (libqsoe owns the chid namespace per process,
          monotonically incrementing).
    \item \texttt{taskman} retypes one Endpoint object from its untyped
          pool, copies the master capability into a fresh slot in the
          caller's CSpace (the \emph{recv slot}), and inserts a row
          into the channel registry (\S\ref{sec:registries}).
    \item \emph{libqsoe} records \texttt{(chid $\to$ recv slot)} in its
          per-process table and returns the chid.
\end{itemize}

\paragraph{\texttt{ChannelDestroy(chid)}}
Atomically tears down a channel the caller owns.  After this call
returns, every client's connection to this channel is invalidated, any
blocked \texttt{MsgReceive} on the channel returns, and any blocked
\texttt{MsgSend} on the client side returns \texttt{EBADF}.  Errors:
\texttt{EBADF} if the chid is unknown to the caller's libqsoe, or
\texttt{ESRCH} if taskman's registry has no matching entry (which
indicates a corruption and is treated as a fatal assertion in debug
builds).

Internally, taskman performs one \texttt{seL4\_CNode\_Revoke} on the
master capability.  By the invariant in \S\ref{sec:registries} that
single call removes the server's recv copy and every client's Send
copy in one step.

\subsection{Connections}
\label{sec:connections}

\begin{lstlisting}[language=C]
int ConnectAttach(uint32_t nd, pid_t pid, int chid,
                  unsigned index, int flags);
int ConnectDetach(int coid);
\end{lstlisting}

A \emph{connection} is the client-side handle to another process's
channel.  Each connection corresponds to a distinct badged copy of the
target channel's Endpoint capability.

\paragraph{\texttt{ConnectAttach(nd, pid, chid, index, flags)}}
Obtains a connection to channel \texttt{chid} owned by process
\texttt{pid}.  Returns a non-negative \texttt{coid} on success.
Parameter semantics:

\begin{itemize}
    \item \texttt{nd} (node descriptor): must be \texttt{ND\_LOCAL\_NODE}
          ($=0$) in v0.x.  Non-zero values are reserved for future
          networked QSOE and return \texttt{EHOSTUNREACH}.
    \item \texttt{pid}: the target server's process ID.  Returns
          \texttt{ESRCH} if no such process or no channel \texttt{chid}
          exists.
    \item \texttt{chid}: the server-local channel identifier.
    \item \texttt{index}: QNX reserves slot 0 for system use; otherwise
          this is informational.  v0.x accepts any value and ignores.
    \item \texttt{flags}: stored in the connection ledger for future
          \texttt{MsgSend} behavior.  v0.x accepts any value.
\end{itemize}

Internally, taskman locates the channel via its
\texttt{(pid, chid) $\to$ master cap} lookup, picks a fresh badge
(monotonic per channel), mints a Send-rights capability with that
badge into a fresh slot in the caller's CSpace, and inserts an entry
into the connection ledger.  The badge is what the server reads on
\texttt{MsgReceive} to identify which client sent the message; in QNX
terms it is the foundation of the \texttt{rcvid}.

\paragraph{\texttt{ConnectDetach(coid)}}
Tears down a single connection.  Returns 0 on success, \texttt{-1} with
\texttt{errno} on failure.  After this call returns, future
\texttt{MsgSend} on this coid returns \texttt{EBADF}.

ConnectDetach is implemented as a round-trip IPC to taskman rather than
a purely local capability delete.  The cost is one extra IPC per
detach; the benefit is that taskman's connection ledger remains an
accurate global record, which simplifies \texttt{ChannelDestroy}
accounting, process-exit cleanup (\S\ref{sec:exit-cleanup}), and
future diagnostics.

\subsection{Messages}

\begin{lstlisting}[language=C]
int MsgSend(int coid, const void *smsg, int sbytes,
            void *rmsg, int rbytes);
int MsgReceive(int chid, void *msg, int bytes,
               struct _msg_info *info);
int MsgReply(int rcvid, int status,
             const void *msg, int bytes);
int MsgSendPulse(int coid, int priority,
                 int code, int value);
\end{lstlisting}

These form the fundamental Send/Receive/Reply triad.  The synchronous
variants map directly to \texttt{seL4\_Call}, \texttt{seL4\_Recv}, and
\texttt{seL4\_Reply}.  Pulses use seL4 Notification objects.

\section{State split: libqsoe vs taskman}
\label{sec:state-split}

For every piece of IPC-related state QSOE tracks, exactly one component
owns it: either \emph{libqsoe} (per process, linked into every program)
or \emph{taskman} (a single central registry).  The split is governed
by one principle:

\begin{quote}
A datum lives in \texttt{taskman} iff \emph{any} of the following holds:
(1) it must be visible across processes; (2) it must survive a crash of
the process that registered it; (3) it is the sole authority for
issuing or destroying a kernel object.  Everything else lives in
libqsoe.
\end{quote}

Table~\ref{tab:state-split} applies that principle to the IPC state
introduced by Chapter~\ref{chap:libqsoe}'s four core functions.

\begin{table}[ht]
\centering
\small
\begin{tabular}{@{}p{6.5cm}lp{5cm}@{}}
    \toprule
    \textbf{State}                                & \textbf{Owner} & \textbf{Notes} \\
    \midrule
    Master Endpoint cap for a channel             & taskman & needed to mint Send caps and revoke on destroy \\
    Channel registry $(pid, chid) \to$ master cap & taskman & consulted by every \texttt{ConnectAttach} \\
    Connection ledger $(channel, badge) \to$ client pid & taskman & enables destroy and exit cleanup \\
    Server's recv cap for its own channel         & libqsoe & derived copy in process CSpace \\
    $chid \to$ recv-cap slot table                & libqsoe & per-process; chid is an opaque handle \\
    $coid \to$ send-cap slot table                & libqsoe & per-process; coid is an opaque handle \\
    Next free chid / coid counter                 & libqsoe & two pools per type --- FD and side-channel (see \S\ref{sec:coid-namespace}) \\
    Process table $pid \to$ TCB/VSpace/CSpace     & taskman & populated by \texttt{tm\_spawn} (v0.3) or future \texttt{ProcessCreate} \\
    Per-connection flags (\texttt{COF\_CLOEXEC}, \ldots) & taskman & mutated by \texttt{ConnectFlags}; read by exec/exit cleanup (v0.4+) \\
    \bottomrule
\end{tabular}
\caption{State ownership for the core IPC functions}
\label{tab:state-split}
\end{table}

Two consequences are worth highlighting:

\begin{enumerate}
    \item \emph{chid and coid are process-local handles}, not kernel
          identifiers.  They are libqsoe's index into its own slot
          tables; taskman keys its registry by the underlying
          capability slot, not by the chid value.  This matches QNX
          semantics exactly: a chid is meaningful only to its owning
          process.
    \item \emph{The master capability is the single point of truth} for
          a channel's existence.  Holding it in taskman --- and nowhere
          else --- is what makes the destroy and process-exit paths
          single-call operations rather than searches.
\end{enumerate}

\section{The coid namespace and SYSMGR\_COID}
\label{sec:coid-namespace}

In QNX, the integer returned by \texttt{open()} is the same value as
the \emph{connection-id} (\emph{coid}) the kernel uses for IPC.  In
other words, \texttt{fd} and \texttt{coid} share a single per-process
namespace.  Standard fds 0/1/2 (stdin/stdout/stderr) are coids 0/1/2;
\texttt{read(fd, ...)} is internally a \texttt{MsgSend(coid, ...)} with
an IO-protocol header.  This is a feature, not a coincidence: the same
code path serves both ``send a message'' and ``read from a file''.

The QNX-style design therefore needs a way to make the implicit
connection to the system process (\texttt{taskman}) coexist with the
FD namespace without colliding with stdio.  QNX solves this by
allocating that connection out of a separate \emph{side-channel}
sub-namespace, marked by bit~30 of the coid:

\begin{quote}
\texttt{QSOE\_SIDE\_CHANNEL} $= 0x4000{,}0000$ \quad
\texttt{SYSMGR\_COID} $= $ \texttt{QSOE\_SIDE\_CHANNEL}
\end{quote}

Every QSOE process is born with this pre-bound side-channel coid;
\texttt{spawn.c} mints the underlying Send capability into the child's
\texttt{QSOE\_CAP\_TASKMAN\_EP} slot (CSpace slot 1, badged with the
child's pid) and the libqsoe init hook records the slot in the
side-coid pool at index 0.  No explicit \texttt{ConnectAttach} is
required to talk to taskman --- the connection is part of the process's
birth certificate.

libqsoe maintains two disjoint pools for each of $chid$ and $coid$:

\begin{table}[ht]
\centering
\small
\begin{tabular}{@{}lll@{}}
    \toprule
    \textbf{Pool}                & \textbf{Value range}                        & \textbf{Use} \\
    \midrule
    FD-range chid                & $1 \ldots N_{\mathrm{ch}}-1$                & user-allocated channels (\texttt{ChannelCreate}) \\
    Side-channel chid            & \texttt{QSOE\_SIDE\_CHANNEL} $|\, i$         & library-internal channels (timers, signals) \\
    FD-range coid                & $1 \ldots N_{\mathrm{co}}-1$                & shares namespace with future libc file descriptors \\
    Side-channel coid            & \texttt{QSOE\_SIDE\_CHANNEL} $|\, i$         & SYSMGR\_COID (index 0) + future library connections \\
    \bottomrule
\end{tabular}
\caption{The four libqsoe handle pools (v0.3.3)}
\label{tab:pools}
\end{table}

The pool is selected at allocation time by inspecting bit~30 of the
\texttt{flags} argument: \texttt{ChannelCreate(QSOE\_SIDE\_CHANNEL)} or
\texttt{ConnectAttach(... flags=QSOE\_SIDE\_CHANNEL)} returns a
side-channel handle; flag~0 returns an FD-range handle.

\subsection{Connection introspection}
\label{sec:connect-info}

Three QNX-compatible calls expose connection state:

\begin{itemize}
    \item \texttt{ConnectServerInfo(pid, coid, *info)} --- client side:
          fills \emph{server's} pid/chid/scoid for the connection.
    \item \texttt{ConnectClientInfo(scoid, *info, ngroups)} --- server
          side: fills \emph{client's} pid (and uid/gid/sid stubs).
          The \texttt{scoid} the server passes is the value
          \texttt{MsgReceive} wrote into \texttt{info->scoid} for that
          message.
    \item \texttt{ConnectFlags(pid, coid, mask, bits)} --- atomic flag
          mutation on a connection (\texttt{COF\_CLOEXEC},
          \texttt{COF\_NONBLOCK}, \ldots).  Returns the previous value;
          \texttt{mask==0} performs a pure query.
\end{itemize}

In v0.3.3, \texttt{scoid} is defined to equal the seL4 \emph{badge}
that taskman minted for the connection: a one-to-one mapping with the
connection registry.  Once QSOE has multiple server processes (v0.4+),
each server will get its own scoid namespace and an explicit
badge$\to$scoid translation table.  The \texttt{pid} argument of
\texttt{ConnectServerInfo} and \texttt{ConnectFlags} must currently be
0 (caller's own process) or \texttt{qsoe\_self\_pid}; any other value
returns \texttt{ENOSYS}.

\section{Wire protocol}
\label{sec:wire-protocol}

Each of the four core functions is a \texttt{seL4\_Call} from libqsoe
to taskman's primary endpoint.  The message info \emph{label} encodes
the request kind; the message registers (MR0--MR3) carry arguments.
Each reply uses label \texttt{0} for success or a negative
errno-style code for failure.

\begin{table}[ht]
\centering
\small
\begin{tabular}{@{}lcccccc@{}}
    \toprule
    \textbf{Request}      & \textbf{Label} & \textbf{MR0} & \textbf{MR1} & \textbf{MR2} & \textbf{MR3} & \textbf{Reply MR0} \\
    \midrule
    \texttt{CHANNEL\_CREATE}        & 0x01 & chid           & flags   & ---     & --- & recv slot \\
    \texttt{CHANNEL\_DESTROY}       & 0x02 & recv slot      & ---     & ---     & --- & ---       \\
    \texttt{CONNECT\_ATTACH}        & 0x03 & target pid     & chid    & flags   & --- & send slot \\
    \texttt{CONNECT\_DETACH}        & 0x04 & send slot      & ---     & ---     & --- & ---       \\
    \texttt{CONNECT\_SERVER\_INFO}  & 0x05 & send slot      & ---     & ---     & --- & server pid; MR1: chid; MR2: scoid \\
    \texttt{CONNECT\_CLIENT\_INFO}  & 0x06 & scoid          & ---     & ---     & --- & client pid; MR1: sid; MR2: flags \\
    \texttt{CONNECT\_FLAGS}         & 0x07 & send slot      & mask    & bits    & --- & previous flags \\
    \bottomrule
\end{tabular}
\caption{libqsoe$\leftrightarrow$taskman wire format (v0.x)}
\label{tab:wire}
\end{table}

The slot numbers exchanged across the wire are CNode-slot indices in
the caller's own CSpace --- taskman holds the caller's root CNode
capability (populated by \texttt{ProcessCreate}) and uses it to copy,
mint, and delete capabilities in the caller's slots directly.  No
capability is transferred \emph{in the message} (\texttt{extraCaps=0}
on all four calls); instead taskman writes capabilities into the
caller's CSpace using \texttt{seL4\_CNode\_Copy} and
\texttt{seL4\_CNode\_Mint}.  This avoids the per-message capability-
unwrapping overhead and makes the wire format a flat integer-only
protocol.

\section{CSpace conventions}
\label{sec:cspace-conventions}

Every QSOE process has a CNode large enough to hold the well-known
caps, the dynamic capabilities allocated by libqsoe (one slot per chid
and per coid), and headroom.  Currently \texttt{ProcessCreate} (when
implemented) sizes process CNodes at $2^{12}$ slots; this is
provisional and will be revisited when real workloads exist.

The reserved-slot layout below is fixed across QSOE.  Constants live
in the header \texttt{qsoe/slots.h} (under
\texttt{userland/libqsoe/include/}) and are included by both libqsoe
and taskman.

\begin{table}[ht]
\centering
\small
\begin{tabular}{@{}lll@{}}
    \toprule
    \textbf{Slot} & \textbf{Symbol}              & \textbf{Contents} \\
    \midrule
    0    & ---                                   & null / reserved \\
    1    & \texttt{QSOE\_CAP\_TASKMAN\_EP}        & Send cap to taskman's primary endpoint \\
    2--15 & ---                                  & reserved for future well-known caps \\
    16+  & ---                                   & dynamic allocations (chid recv slots, coid send slots) \\
    \bottomrule
\end{tabular}
\caption{Reserved CSpace slots in every QSOE process}
\label{tab:cspace}
\end{table}

The taskman process itself is the only exception: its CSpace is the
initial root-task CNode from \texttt{seL4\_BootInfo}, populated
according to seL4's conventions rather than QSOE's.  Taskman maintains
its own internal mapping from QSOE slot semantics to the actual
BootInfo slot numbers.

When \texttt{tm\_spawn} mints \texttt{QSOE\_CAP\_TASKMAN\_EP} into a
new child's slot 1, it also registers a connection record in taskman's
connection registry, keyed by (\texttt{client\_pid}, slot 1)
and badged with the child's pid.  Without this record, the child's
first \texttt{ConnectServerInfo} or \texttt{ConnectFlags} call would
\texttt{EBADF}: SYSMGR\_COID is established by minting, not by
\texttt{ConnectAttach}, so the registry would otherwise have nothing
to look up.

\section{Threading}

\begin{lstlisting}[language=C]
int ThreadCreate(pid_t pid, void *(*func)(void *),
                 void *arg, const struct _thread_attr *attr);
int ThreadDestroy(int tid, int priority, void *status);
\end{lstlisting}

Thread creation allocates a new seL4 TCB (Thread Control Block),
configures its scheduling parameters, and starts execution at the
specified function.

\section{Relationship to musl libc}

Standard C/POSIX functions (\texttt{printf}, \texttt{malloc},
\texttt{open}, \texttt{read}, etc.) are provided by musl libc, patched
to route system calls through seL4 IPC to \texttt{taskman} or the
appropriate resource manager rather than through Linux \texttt{ecall}
traps.
